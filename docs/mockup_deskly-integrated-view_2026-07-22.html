QA hub 統合画面 — 役割別ビュー UI モック

2026-07-22 / owner: ishizakahiroshi / モード: mockup 草案

QA を投げるだけでは進捗が見えないため、統合ダッシュボード（QA hub NC app）を Nextcloud 上に構築する。 権限は NC Group で分離し、関係ないシステム / 顧客のデータは UI に一切出さない（見えるものだけが自分の担当領域）。経営層は全部、部長は担当システム 2 つ、担当者は 1 つ、といった役割別の見え方の差分をこの資料で認識合わせする。

画面リスト

S-01

経営層ビュー

自社全システム × 全ステータスのダッシュボード。KPI サマリと未対応の山を俯瞰。

S-02

部長ビュー

自分が管掌する 2 システムだけ。担当者アサイン・SLA 監視が主用途。

S-03

担当者ビュー

自分の 1 システムのみ。自分にアサインされた QA と担当外の一覧に絞る。

S-04

顧客一般ユーザービュー

自分が起票した QA のみ。他人の QA は見えない。追記・添付は可能。

S-05

Meijie super-admin

Mercury / Timely / 他社の全顧客横断。customer_id フィルタで切り替え。

S-06

チケット詳細モーダル

S-01〜S-05 共通。履歴・コメント・添付・状態変更・アサイン変更。

全ビュー共通。表示可否はチケットの customer_id / system_id と閲覧者の Group で決定。編集可否は role で分岐。

権限モデル（NC Group 分離）

NC の Group 機能で権限を表現する。追加の権限 DB は持たない。Group 命名規則: qa-<role>-<scope>。

Group 意味 customer_id system_id 他人の QA 編集
qa-admin-meijie Meijie super-admin（全顧客横断） 全て 全て 可 可
qa-admin-<customer> 顧客側 admin（自社全システム） 自社のみ 全て 可 可
qa-viewer-<customer>-exec 顧客経営層（自社全システム read-only） 自社のみ 全て 可 不可
qa-manager-<system> 特定システム部長 自社のみ 指定分 可 可
qa-staff-<system> 特定システム担当者 自社のみ 1 つ 同システムのみ 可
（Group 未所属） 一般ユーザー（default: qa-user） 自社のみ 起票済のみ 不可 自分の起票のみ

複数 Group に所属した場合は 権限の和集合（例: 部長 A + 部長 B の 2 兼任 → 両システム見える）。super-admin は customer_id 制約を持たないので、集約 opt-in された全顧客が見える。

未決定事項

  • 添付画像の保存先: NC Files 直接（ACL 継承・プレビュー統合）vs チケット内包 BLOB（app 単独完結）。前者推奨だが権限伝播設計が必要
  • コメントの通知タイミング: 全変更即時 / 1 時間まとめ / メール daily digest。人によって好みが分かれる、ユーザー設定を持たせるか固定運用か
  • 対応者アサインの UI: drop-down（担当者候補リストから選択）vs @mention（コメント内で自然にアサイン）。運用文化に依存
  • 顧客側からの再オープン可否: 完了済チケットを起票者が再オープンできるか。可にすると SLA 計算が複雑化、不可にすると新規起票が増える
  • モバイル UI: NC assistant 統合（既存モバイル NC アプリ + AI chat）/ 独立 PWA（QA hub 専用）/ NC モバイルアプリ内 webview（NC 標準）のどれを主導線にするか
  • SLA の定義と可視化: SLA 何日にする？超過警告の色・タイミング。優先度別に SLA 差をつけるか
  • 優先度の運用: 高 / 中 / 低の 3 段で足りるか。誰が付ける（起票者 / 対応者 / 部長）
  • Group 命名の legal name 対応: qa-viewer-mercury-exec のような命名で顧客名を直接使うか、顧客 code（c001 等）を使うか。契約上の中立性への配慮
  • 集約 opt-in の UI: 顧客側 admin が Meijie 集約を on/off する画面をどこに置くか（NC 設定画面 / hub app 設定）
  • 削除・アーカイブポリシー: 何年で自動アーカイブか、削除は誰の権限か、監査ログをどう残すか
